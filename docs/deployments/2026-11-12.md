# Hosted releases — November 12, 2026

## Longview Planner public site and private cloud saving

Production is now **https://longview-planner.pages.dev**. The site requires no login for local planning. Anyone can create an optional username/password account, save an account recovery code, and set up an end-to-end-encrypted vault. This supersedes the invitation-only Access/R2 hosting plan for the public site.

Cloudflare Pages serves the app and same-origin account API. D1 database `longview-planner` (`cbb94af7-2a67-469a-a471-1b6e63834a39`) holds account records, encrypted plans, wrapped keys and metadata. Migrations `0001`–`0003` were applied, and `AUTH_SECRET` is a Pages production secret. No paid plan or R2 subscription was selected. Per-account storage is capped at 20 live plans / 2 MiB, with 256 KiB per plan; provider-wide free quotas also apply.

Live verification covered public anonymous access, username signup, sign-in, vault creation, automatic encrypted upload, a separate browser downloading/decrypting a sample plan, and mobile layout without horizontal overflow. Account recovery was verified against production: a valid code reset the password, revoked old sessions and rotated the code; replay and a foreign origin were rejected. The PWA's “Reload now” action successfully loaded the updated app.

The original sync client did not accept compression-weakened ETags; this release adds an explicit version header and weak-ETag compatibility with regression coverage. It also preserves edits made during uploads and uses the version seen before an offline deletion, so a newer cloud edit becomes a conflict instead of being silently deleted. All plan content in verification was fictional.

Local release checks: 456 unit/property tests passed with two existing TODOs; 132 browser tests passed with 31 intentional project skips; Lighthouse passed its assertions on three runs; typecheck, lint and format passed. The production dependency audit has no high/critical findings (four moderate advisories remain). Account isolation, atomic versioning/quotas, logout, recovery replay protection and rate limits have automated backend tests; frontend regressions cover compressed response headers and in-flight/offline edits. A live offline edit was retained and synced to the other browser after reconnecting.

Publication still uses locally authorized Wrangler. GitHub runs all checks, and its updated deployment workflow is ready for this Pages/D1 architecture, but repository Cloudflare deployment credentials have not been configured. See the [public cloud runbook](../runbooks/public-cloud.md) for limits, recovery and commands. The final release should be published from the exact passing CI artifact.

The previous site remains available below. Browser-local data does not automatically transfer to the new hostname; use encrypted export/import in Settings.

### Operating limits of the initial release

This release serves the complete local-first app. No personal plan data was uploaded with the static site. Plans created on localhost do not automatically appear on the hosted origin; use the app's encrypted backup/export and import to transfer them.

Cloud sync, D1/R2 resources and GitHub's Cloudflare deployment secrets remain unconfigured. This was an authenticated manual upload of the CI artifact. Future pushes run checks but do not automatically publish until the deployment credentials and optional sync pipeline are configured. Do not copy a short-lived local OAuth token into repository secrets.

At the owner's request, the production hostname was removed from Access after the initial protected deployment. Unauthenticated requests to the production site return HTTP 200 and the app HTML; preview/deployment URLs still return the Access redirect. The generated Access application provides email-code sign-in for allowed account members on those preview URLs. Its dashboard also shows a Zero Trust plan-onboarding prompt; no paid plan was selected. Review that account setup before expanding access or deploying the optional sync service.

For rollback after a subsequent release, select this Pages deployment in Cloudflare. Preserve preview protection and public access to the production hostname. There was no Worker release or D1 migration in this deployment.
