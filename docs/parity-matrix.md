# Parity matrix

Every feature ID from [plan](../plan/BUILD_PLAN.md) §4 and §9. This is the working copy of the parity
matrix: the v1.0 gate (plan §16) requires every row to be implemented, tested and marked `done`.

- **Phase** is the roadmap phase that delivers the feature (plan §15). Where a feature lands in stages, the
  phases are listed with what each adds.
- **Status** is one of `done` (implemented, and the tests listed exercise it), `untested` (implemented, but only
  covered indirectly, with no dedicated test), or `partial` (implemented with the gap stated in the Tests column).
  As of data release data-2026.1: 54 done, 10 untested, 12 partial. The v1.0 gate is therefore **not met**.
- **Where implemented** lists the main source paths. **Tests** lists the test files, validation cases
  (V-01 to V-09) and tour IDs that cover the feature. A user-facing feature is not `done` until its tour
  steps pass (plan §10.2).
- Capabilities seen on the design reference board that have no ID yet are listed, with proposals, in
  [design/reference-map.md](design/reference-map.md#capabilities-with-no-feature-id). They are not rows
  here until the plan is amended.

76 feature IDs: PLAN 14, SIM 10, TAX 14, STRAT 4, HC 12, RPT 6, SYNC 4, UX 12.
